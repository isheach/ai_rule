# 会话模式、真实调用链与开场提示词

规则修订：2026-11-10.dispatch-chain-r2。沿用 session-mode-r1 的会话保持规则，补全真实 Sol 派单要求。

## 目标

用户只需选择一次执行模式。同一会话的后续任务、修复、测试和必要监守保持该模式，除非用户明确切换。
“默认 A”只用于全新会话尚未选择模式时，不能被解释为“本条消息没写模式就恢复 A”。

模式可选 A、HY4、WorkBuddy DeepSeek、DSH。职责以仓库 AGENTS.md 为准：A 由 Sol Max 执行，必要时 Luna 监守；外部模式由真实 Sol Max 规划、调度和验收，指定后端执行和自行监守，不使用 Luna。

## 实际调用链与证据

在 Astra 主会话中，外部执行必须采用：

```text
Astra 主代理：总体目标、重大决策、用户沟通
    ↓ 实际创建或恢复真实子代理
GPT-6.1 Sol Max（max）：规划、实际派单、等待、验收、修订派单
    ↓ 在 Sol 自己的执行上下文调用所选 MCP
DSH / WorkBuddy：实际执行、自测、修复及必要监守
```

DSH 的模型推理由 OpenCode Go API 提供，不使用 OpenCode CLI。主会话本身经宿主证实为 Sol 时无需再创建一个同角色层级；不得让 Astra 自称 Sol 规避要求。
Astra 用原生 wait 等待 Sol 的真实 agent ID；Sol 用 MCP wait 等待外部 task_id。一个任务只允许一个协调者，优先复用已有 Sol。
Astra 不直接提交、修订或日常轮询外部任务。只创建 Sol 却自己调用 DSH，即使任务成功也属于调用链不合格。用户明确要求的只读审计或紧急停止是需记录的例外，不授权后续越级派单。
Sol 工具缺失/拒绝时应阻塞并上报，不由 Astra 转发，也不允许 Sol 亲自实现任务。

最小验收信息包括：Sol 真实 agent ID、宿主模型和档位依据、实际 MCP 调用发起方记录、task_id 和终态。用户已经报告本机映射为 gpt-6.1-sol/max；昵称、提示词和模型自述不等于宿主记录。不要自造创建工具参数。
DSH RUN_RECEIPT 不能独立证明上游是谁调用了 MCP；也不能把 actual_route=null 改写为已验证服务端型号。身份不明就报告未核实。
这些是报告/交接项，不是 MCP 新参数。首次、换协调者或出现违规时做针对性核查；日常只保留最小证据，不为每一步反复读取整个历史、重复模型测试或叠加多轮审查。

## 作用范围与切换

- 会话保持：用户说“使用 DSH，分析……”就建立 DSH 会话模式，无须说“全程”。后续不写模式则保持。
- 明确切换：用户说“改用原生 A”后，以 A 作为后续会话模式。只是提到或比较另一个模型不构成切换。
- 一次性例外：用户明确说“仅本次用 X”才临时覆盖当前任务，结束后恢复原模式。普通“使用 X”默认是会话选择。
- 运行中任务：记录 task_backend，不能因为会话选择变更就偷偷转移原进程、并发修改相同文件或重启任务。按授权等待、停止或交接后再迁移。
- 不可用后端：保持选择并报告阻塞，不自动换成 Sol、Luna、其他后端或付费渠道；不自动安装缺失服务。唯一例外是显式授权、结构化证明“未受理”的 DSH→HY4 预准入回退（见 `docs/hy4-fallback.md`）；默认策略未接入，HY4 未验证，因此当前仍以阻塞为准。
- 新会话：不继承无关旧会话或另一电脑的临时模式，未指定则 A。用户明确恢复原会话或要求沿用可信交接时，可恢复该选择；没有证据就确认，不猜测。

session_mode 应随当前会话的摘要/交接保留，包括选择依据、协调者 agent ID、活动任务 ID 和任务后端。不要将它写入共享全局配置，避免两台电脑或多个并发会话互相覆盖。
模式保持不扩大权限，不自动开放 workspace-write，不授权删除、安装、提交、推送或扩大访问目录。

## 可直接复制的 DSH 开场提示词

发给 Codex 的会话输入框，不是在 PowerShell 中执行：

```text
本会话使用 DSH 模式。请读取当前生效的 AGENTS.md 和 multi-agent-dispatch Skill。

Astra 负责总体方向，必须创建或恢复真实 GPT-6.1 Sol Max（max）子代理。由 Sol 在自己的上下文实际调用 DSH MCP，负责规划、状态管理、等待、验收和修订派单。Astra 不直接派单，不把 Sol 只当顾问。
具体执行、测试、修复及必要监守交给 DSH 原生 Harness 的 DeepSeek；Sol 不代执行，不使用 Luna，也不经过 OpenCode CLI。

除非我明确指定切换模式，否则本会话后续任务一直沿用当前模式，包括“继续”“修改一下”“运行测试”等指令。只有全新会话从未指定模式时，才使用默认 A；若我明确切换，则后续持续使用新模式。

后端或 Sol 的 MCP 工具不可用时报告阻塞，不自动回退，不由 Astra 转发；只有本机显式启用并验证的预准入 HY4 策略可在“未受理”时按规则转一次。选择执行模式不是永久写入授权，继续遵守已批准的操作范围。
先简短确认模式和真实协调者；我的第一个任务是：先只读分析当前项目结构。
```

已安装新规则时，可缩短为：

```text
本会话使用 DSH，由真实 Sol Max 子代理派单。除非我明确切换，否则后续一直沿用。先只读分析当前项目。
```

新会话完全不指定模式，则按 A 处理，无需一段默认模式提示词。

## 旧会话出现越级派单后的修复

1. 暂停新增越级派单，保留已经完成的成果。不为修正架构重做实验。
2. 有活跃任务时保留原宿主和 MCP 进程，不立即重启 Codex、不取消任务、不清理锁。旧的 running 报告可能已过时，先核实当前状态。
3. 更新本机规则后，要求 Astra 和 Sol 分别读取生效 AGENTS 和 Skill。优先恢复原协调者；无法恢复时才创建替代 Sol，防止两个协调者并行接管。
4. 交接真实 task_id、cwd、回执位置、已知幂等键、授权范围及状态时间。Sol 能安全访问原任务时仅接续查询/验收，不重新 start。
5. 不同 MCP 实例可能不能继承进程所有权；出现 unknown_after_disconnect 等情况就报告限制，保留原进程并等待自然完成，必要的额外处置请求授权。读到回执不等于获得取消/恢复权限。
6. 确认旧任务终态并验收后，由 Sol 提交下一项必要任务。首个新任务必须核对真实调用归属；不能用旧的工具成功回执冒充新调用链验收。

旧会话指令示例：

```text
请读取刚安装的 dispatch-chain-r2 规则，继续保持 DSH 模式。
保留现有成果及正在运行的任务，不取消、不重启、不重复提交。
优先恢复原来的真实 Sol Max（max）子代理；不能恢复才建立替代协调者。
将现有任务 ID、cwd、回执和授权范围移交给 Sol；能安全访问时由它接续状态查询与验收，否则报告限制并保留原 MCP 进程等待自然完成。
之后所有 DSH 提交、等待、修订及验收必须实际发生在 Sol 子代理上下文。Astra 不转发；Sol 不代替 DSH 执行；不用 Luna。
先确认交接和任务现状，不新增实验。无需重新做已通过的连接测试；下一项已授权的真实任务再验证调用发起方。
```

## 本次同步方式

```powershell
Set-Location "$env:USERPROFILE\ai_rule" -ErrorAction Stop
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "Git 同步失败，停止安装。" }
node .\scripts\manage.mjs
if ($LASTEXITCODE -ne 0) { throw "预览失败，停止安装。" }
# 确认只更新规则/Skill，再运行：
node .\scripts\manage.mjs --apply
if ($LASTEXITCODE -ne 0) { throw "规则安装失败。" }
node .\scripts\manage.mjs --verify
```

本次不带 --enable-dsh，不重写 MCP 注册，也不改变已有写权限。两台电脑各同步一次，GitHub 提交不自动推送到本机，更不会自动注入已运行会话。若 pull 涉及本次预期之外的 bridges/scripts 变动，停止并先评估活动任务。
有活跃任务时显式重读规则，不重启宿主；安全结束后再重启或开新会话核实启动加载。
电脑 B 暂不部署 WorkBuddy；HY4/WorkBuddy DeepSeek 检查为 false 是允许的配置，不触发补装。

## 手工行为验收场景（预期，不代表已执行）

| 场景 | 预期 |
|---|---|
| 全新会话未指定后端 | A |
| “使用 DSH，先分析代码”后说“继续分析另一个模块” | 两次都由真实 Sol 派单，DSH 执行 |
| DSH 任务完成后说“现在再检查测试” | 仍为 DSH，不重置 A |
| 已选 DSH 后问“HY4 是否更便宜” | 保持 DSH |
| 已选 DSH 后明确“切换到 A” | 后续 A；现有任务按授权妥善结束/交接 |
| 已选 DSH 后明确“仅本次使用 A”，下个任务不写模式 | 该次 A，之后恢复 DSH |
| DSH 认证失败、忙碌或超时 | 默认保留 DSH、报告阻塞；已受理/超时/断连不回退，busy 也不自动回退 |
| DSH 日程门禁在受理前拒绝，且本机显式授权、HY4 已验证 | 可按策略最多转 HY4 一次并记录决策；否则保留 DSH 阻塞 |
| 已选 DSH 但 HY4 未验证/未部署 | 不猜测通用 CodeBuddy 模型，不回退；报告缺失入口 |
| 独立新会话未指定 | A，不受另一个会话选择影响 |
| 恢复原会话或明确要求延续交接中的 DSH | 依据记录恢复 DSH 和协调者信息 |
| 当前模式只读，用户只说“继续” | 保持模式和授权边界，不扩大权限 |
| 电脑 B 未部署 WorkBuddy，用户指定 HY4 | 报告未部署，不自行安装或切换 |
| 已创建 Sol，但 Astra 自己 start_dsh_task | 调度链不合格；保留成果，纠正后续派单 |
| Sol 看不到外部工具 | 报告阻塞，不让 Astra 代发 |
| Sol 实际提交，UI 汇总显示在主时间线 | 以宿主实际调用归属为准，不凭 UI 位置判断 |
| 旧任务由 Astra 提交且仍在运行 | 保留原进程，只安全交接，不重启/重复提交 |
| 只有 DSH 回执、没有调用发起方记录 | 任务结果可验收，调用者身份仍未独立核实 |

## 实现边界

本次仅修改 AGENTS.md、Skill、README 和本说明，没有修改桥接器、安装器、凭据或工具注册；没有增加调用者认证、进程级路由强制器或全局可变状态文件。
规则是否被宿主加载、Sol 是否能调用 MCP、调用链是否符合要求，需要真实宿主记录检验。不能声称仅改文档就能百分之百阻止代理偏离，也不能信任模型自行传入的身份字段来代替认证。
MCP 桥接器已有的单任务状态、幂等与任务 ID 不等于这里的会话模式或协调者身份。对话上下文丢失时应先恢复记录，而不是利用未知状态静默切换。
当前更新基于用户提供的本机调度审计；未访问用户本机完整会话日志，也未代其操控仍在运行的任务。本次只核对规则/文档差异，未运行新的宿主端到端验收。
