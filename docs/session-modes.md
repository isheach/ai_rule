# 会话模式保持与开场提示词

规则修订：2026-11-10.session-mode-r1。

## 目标

用户只需选择一次执行模式。同一会话的后续任务、修复、测试和必要监守保持该模式，除非用户明确切换。
“默认 A”只用于全新会话尚未选择模式时，不能被解释为“本条消息没写模式就恢复 A”。

模式可选 A、HY4、WorkBuddy DeepSeek、DSH。职责以仓库 AGENTS.md 为准：A 由 Sol Max 执行，必要时 Luna 监守；外部模式由 Sol Max 规划、调度和验收，指定后端执行和自行监守，不使用 Luna。

## 作用范围与切换

- 会话保持：用户说“使用 DSH，分析……”就建立 DSH 会话模式，无须说“全程”。后续不写模式则保持。
- 明确切换：用户说“改用原生 A”后，以 A 作为后续会话模式。只是提到或比较另一个模型不构成切换。
- 一次性例外：用户明确说“仅本次用 X”才临时覆盖当前任务，结束后恢复原模式。普通“使用 X”默认是会话选择。
- 运行中任务：记录 task_backend，不能因为会话选择变更就偷偷转移原进程、并发修改相同文件或重启任务。按授权等待、停止或交接后再迁移。
- 不可用后端：保持选择并报告阻塞，不自动换成 Sol、Luna、其他后端或付费渠道；不自动安装缺失服务。
- 新会话：不继承无关旧会话或另一电脑的临时模式，未指定则 A。用户明确恢复原会话或要求沿用可信交接时，可恢复该选择；没有证据就确认，不猜测。

session_mode 应随当前会话的摘要/交接保留，包括选择依据、活动任务 ID 和任务后端。不要将它写入共享全局配置，避免两台电脑或多个并发会话互相覆盖。
模式保持不扩大权限，不自动开放 workspace-write，不授权删除、安装、提交、推送或扩大访问目录。

## 可直接复制的 DSH 开场提示词

发给 Codex 的会话输入框，不是在 PowerShell 中执行：

```text
本会话使用 DSH 模式。请读取当前生效的 AGENTS.md 和 multi-agent-dispatch Skill。

Astra 负责总体方向；GPT-6.1 Sol Max 只负责规划、调度和验收，不代替子代理修改代码、运行实验或修复错误。具体执行、测试、修复及必要监守交给 DSH 原生 Harness 的 DeepSeek，不使用 Luna，也不经过 OpenCode CLI。

除非我明确指定切换模式，否则本会话后续任务一直沿用当前模式，包括“继续”“修改一下”“运行测试”等指令。只有全新会话从未指定模式时，才使用默认 A；若我明确切换，则后续持续使用新模式。

后端不可用时报告阻塞，不自动回退。选择执行模式不是永久写入授权，继续遵守已批准的操作范围。先简短确认模式和后端是否可用；我的第一个任务是：先只读分析当前项目结构。
```

已安装新规则时，可缩短为：

```text
本会话使用 DSH，除非我明确切换，否则后续一直沿用。先只读分析当前项目。
```

在已进行的会话中发送同样的模式声明，可直接表达当前用户选择；但不能据此假设新版本 Skill 已经被载入，必要时显式读取本机更新后的文件。
新会话完全不指定模式，则按 A 处理，无需一段默认模式提示词。

## 本次同步方式

```powershell
Set-Location "$env:USERPROFILE\ai_rule"
git pull --ff-only
# pull 失败时停止并处理冲突；不要强制覆盖。
node .\scripts\manage.mjs
# 确认只更新规则/Skill，再运行：
node .\scripts\manage.mjs --apply
node .\scripts\manage.mjs --verify
```

本次不带 --enable-dsh，不重写 MCP 注册，也不改变已有写权限。两台电脑各同步一次，之后新会话读取本机规则。GitHub 提交不自动推送到本机，更不会自动注入已运行会话。
电脑 B 暂不部署 WorkBuddy；HY4/WorkBuddy DeepSeek 检查为 false 是允许的配置，不触发补装。

## 手工行为验收场景（预期，不代表已执行）

| 场景 | 预期 |
|---|---|
| 全新会话未指定后端 | A |
| “使用 DSH，先分析代码”后说“继续分析另一个模块” | 两次都由 DSH 执行 |
| DSH 任务完成后说“现在再检查测试” | 仍为 DSH，不重置 A |
| 已选 DSH 后问“HY4 是否更便宜” | 保持 DSH |
| 已选 DSH 后明确“切换到 A” | 后续 A；现有任务按授权妥善结束/交接 |
| 已选 DSH 后明确“仅本次使用 A”，下个任务不写模式 | 该次 A，之后恢复 DSH |
| DSH 认证失败、忙碌或超时 | 保留 DSH，报告阻塞，无隐藏回退 |
| 独立新会话未指定 | A，不受另一个会话选择影响 |
| 恢复原会话或明确要求延续交接中的 DSH | 依据记录恢复 DSH |
| 当前模式只读，用户只说“继续” | 保持模式和授权边界，不扩大权限 |
| 电脑 B 未部署 WorkBuddy，用户指定 HY4 | 报告未部署，不自行安装或切换 |

## 实现边界

本次修改的是 AGENTS.md、Skill 与说明文档，没有增加进程级路由强制器或全局可变状态文件。
规则是否被宿主加载、具体工具是否可调用、模型是否按指令路由，需要通过真实新会话和回执检验；不能声称仅改文档就能百分之百阻止代理偏离。
MCP 桥接器已有的单任务状态、幂等与任务 ID 不等于这里的会话模式。对话上下文丢失时应先恢复记录，而不是利用未知状态静默切换。
