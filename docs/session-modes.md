# 会话操作与验收

将命令式请求直接发送到 Codex 聊天中。完整作用域和角色边界以 [AGENTS.md](../AGENTS.md) 为准，运行过程见 [调度 Skill](../skills/multi-agent-dispatch/SKILL.md)。

## 全新会话与默认

独立新会话默认使用订阅来源、GPT-6.2 Sol Max → DSH/OpenCode Go DSF、峰谷模式 1。WorkBuddy DSF 只是明确选择的底层替代；既有模式 2 的峰时交接按原规则。主机操作/验收、写作、绘图或图像生成与识别交 GPT-6.1 Terra Max，使用与 Sol 相同的已选中间来源。已有 A/外部模式、模式 3、来源和已受理任务不被新默认改写。

## 示例

| 对 Codex 说 | 会话效果 |
|---|---|
| 直接开始这项编码或研究任务。 | 独立新会话用订阅 Sol Max → OpenCode Go DSF，无需先声明。 |
| 本会话使用 DSH，先只读分析当前项目。 | 选择 DSH，按当前 Sol 来源及峰谷选项派发。 |
| 接着看另一个模块。 | 沿用已有选择，任务书换成当前模块。 |
| 本会话底层改用 WorkBuddy DSF，核对已批准项目的实验输入。 | 显式选择 WorkBuddy DSF 底层；协调来源与已有任务不变。 |
| 这次主机操作或验收交给 Terra，完成后关闭 CUA。 | 专家任务；只在宿主实际提供 Terra/CUA 时执行，限定范围结束后关闭。 |
| 这篇文稿或这张图交给 Terra。 | 写作可直接返回文本；图像只在有实际图像工具或预注册动作时执行。 |
| 这两个 DeepSeek 渠道的时段和费用有什么区别？ | 保留会话选择。 |
| 本会话的 Sol 主控切到 API。 | 为后续任务设置 API 协调来源；付费调用仍需授权。 |
| 仅本次用订阅 Sol。 | 一次性覆盖协调来源，用完恢复本会话的既有来源。 |
| 仅本次使用 WorkBuddy DSF。 | 一次性覆盖底层，沿用适用的项目授权和协调来源。 |
| 本会话用峰谷模式 2。 | 更新当前 DSH 会话的日程选择。 |
| 改用原生 A。 | 选择 A。若此时来源为 API，报告组合限制，等待明确选择受支持来源。 |

已经安装规则时，一句明确的选择及本轮目标即可。未选择的独立新会话使用 AGENTS 表中的默认组合。只说 “DSF” 时，已选定的 DSH 或 WorkBuddy DSF 可给出明确渠道依据；默认底层是 DSH/OpenCode Go DSF。

## 有任务的会话重读

可在旧会话发送：

> 请 Astra 和原 Sol 重读当前生效的 AGENTS 和 multi-agent-dispatch Skill，恢复之前的会话设置和已批准范围。Astra 等待原 Sol 的任务结果，原 Sol 按已有回执从原入口继续负责本项工作。

已有越级派单的任务按 Skill 的验收与交接步骤处理。保留已有成果及运行环境。Astra 移交原 ID、幂等键、归属、cwd、授权和已知状态，真实 Sol 在能安全访问时继续查询与验收。无法接续进程所有权时，由原入口完成。 [安全交接步骤](../skills/multi-agent-dispatch/SKILL.md#4-验收恢复与交接)

## 行为验收

用已批准的后续任务核对相关变化。

| 核对场景 | 应见证据 |
|---|---|
| 全新独立会话 | 实际为订阅来源、`gpt-6.2-sol`/max，底层为 OpenCode Go `deepseek-v4.1-flash`；未自动改用 WorkBuddy DSF、A 或 API。 |
| 订阅 Sol 派外部任务 | 宿主记录真实 Sol ID、模型与档位，提交者为该 Sol，执行回执来自选定 Harness。 |
| API Sol 派外部任务 | 协调回执有 Responses 请求和下游实际任务 ID、状态、返回模型及已知用量。 |
| Terra 专家任务 | 实际模型/工具与任务匹配；纯写作有文本结果；动作任务有本地回执；限定范围 CUA 已关闭。API Terra 只出现预注册动作名称，没有通用桌面或图像驱动声明。 |
| 显式换一项会话设置 | 仅该项用于后续任务，已有任务归属和另外两项可从记录恢复。 |
| 限定一次或只讨论某模型 | 一次任务采用明确覆盖，其余沿会话记录。讨论本身保留记录。 |
| 同一会话继续或压缩上下文 | 从可信记录恢复设置、原授权、任务和协调归属。 |
| 后端未部署、权限受限或结果未知 | 可见的阻塞与原任务状态，后续决定有真实用户依据。 |
| 发现工具在主会话时间线集中展示 | 用宿主的实际调用记录核实发起者。DSH 回执用于验证执行层。 |
| API 配额变化 | 新装显示 100；旧缺字段显示 24；已有 96 经显式升级变为 100，且 `rate.bin`/审计记录未被重置。 |

变更规则、安装、调用路径和业务结果是各自可核验的事项。实际环境的证据要求见 [实现与验收](implementation.md)。
